# M3 使用与运维

## 环境与启动

推荐 Node.js 24 LTS；兼容最低 Node.js 22.18。生产驱动为 better-sqlite3，安装时会尝试下载原生预构建文件；没有对应文件的平台需要本机 C/C++ 构建工具。当前开发验证环境为 Linux arm64；其他平台与 Docker 镜像不是本阶段验收范围。

在仓库根目录执行 `npm ci`、`npm run build`、`npm start`，浏览器打开 `http://127.0.0.1:3000`。服务默认绑定 loopback，界面和 API 同源。第一次启动自动创建数据库、独立主密钥和设置令牌；读取启动日志指示位置的 `setup-token` 后在页面创建管理员。设置完成后初始化接口关闭，旧令牌不再有效，可从文件系统删除。

单个数据目录只允许一个服务进程。同步请求返回任务 ID，实际工作在服务器后台完成；关闭网页不会取消任务。停机或整轮超时会中断任务，手动任务可再次点击“立即同步”，已启用的自动同步会按保存的计划/退避状态继续运行。

## 环境配置

可将 `.env.example` 的内容保存为外部应用数据目录下的 `config.env` 后按需修改；`npm start`、`npm run dev` 和 `npm run restore` 使用相同路径规则并读取该文件。进程环境变量优先。不会读取源码目录中的 `.env`。不要把连接凭据填入配置文件，使用页面配置。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| APP_HOST | 127.0.0.1 | 服务监听地址 |
| APP_PORT | 3000 | 监听端口 |
| APP_ORIGIN | http://127.0.0.1:3000 | 浏览器访问源，必须精确匹配，不含尾部斜杠 |
| DATA_DIR | 应用数据目录/data | SQLite 数据目录，可设为源码之外的绝对路径 |
| SECRETS_DIR | 应用数据目录/secrets | 主密钥/初始化令牌目录，可设为源码之外的绝对路径 |

Origin 不一致会拒绝写请求；不要混用 localhost 和 127.0.0.1。配置 HTTPS origin 后会话 Cookie 自动使用 Secure。反向代理部署需保留浏览器 Origin，并转发到内部 HTTP 服务；当前不信任 X-Forwarded-For，因此经代理登录限速按代理地址共享。公网部署使用 HTTPS。当前不提供反向代理、域名或证书的自动配置。

## 连接与同步

微信读书连接保存前读取一次笔记本列表验证凭据；失败不会替换已有连接。保存相同 Key 不改变数据空间，替换 Key 需要勾选确认并创建新空间。M1 没有可靠账号标识，因此不能自动合并不同 Key 对应的笔记；历史数据可在笔记库中选取旧连接查看。

flomo 地址只接受官方 HTTPS 域名和 `/iwh/` 路径格式。保存连接时仅校验格式，不校验实际写入权限，也不发送测试笔记。已保存地址会直接出现在规则的目标连接中，无需再次填写。

每轮读取全部笔记本分页，并对当前列表与数据库已知书籍的并集逐本读取划线、全部想法分页，必要时补书名/作者/章节。同一书籍的一类想法只有读完全部分页才提交；独立书籍或类别可以先成功入库，失败范围保存在同步详情。书籍列表未读完时不提交该次列表。

同一来源 ID 再次出现时更新内容和原始字段；未变化内容不会修改本地更新时间。来源创建时间保存在独立字段，与首次入库时间区别。来源时间不明时显示缺失。想法缺失按下述两次核对机制标记，保留原内容；划线缺失仍保留原状态。“读取完成”不是来源全部现状的强保证。

请求串行、至少间隔 1 秒，网络/5xx/429 最多尝试 3 次。遵守 `Retry-After`；等待要求超过 30 秒时结束当前读取并显示限流/不可用，用户稍后重试。单请求 30 秒、单响应 32 MiB、单轮 30 分钟、分页最多 10,000 页；达到阈值显式失败，不静默截断成成功结果。

## 浏览

笔记库按创建时间倒序，每页 20 条；关键词为字面子串，搜索想法、原文、书名和作者，SQLite LIKE 对 ASCII 英文大小写不敏感。日期范围使用北京时间，包含起止两天；来源创建时间缺失的记录不会匹配日期条件。详情中可查看来源 ID、时间、原文、章节及接口的原始条目 JSON。所有内容按文本显示。

## 备份与恢复

M1 提供停机备份流程，尚未实现页面备份按钮或在线备份任务：

1. 正常停止服务，等待正在执行的同步被标记为中断并关闭数据库。
2. 复制完整 `DATA_DIR`（包括残留的 SQLite WAL/SHM 文件），将 `SECRETS_DIR/master.key` 单独保管；备份内容含私人笔记和加密凭据，不公开上传。
3. 恢复时停止服务，准备匹配的主密钥，再使用下文 `npm run restore -- --from ...` 恢复数据库，保持仅部署用户可读写。
4. 启动后核对 flomo 历史和规则范围，再在“自动任务”解除备份恢复保护。

密钥文件丢失或不匹配时，程序拒绝读取既有凭据，不会生成替代密钥覆盖旧数据。当前没有在丢失密钥情况下恢复旧连接或自动重置管理员的流程；保留可用备份。升级前停机备份，数据库版本高于应用支持版本时拒绝启动，不能直接降级运行。

## 开发

先执行 `npm ci` 和 `npm run build`。两个终端运行：

```sh
APP_ORIGIN=http://127.0.0.1:5173 npm run dev
npm run dev:web
```

浏览器打开 `http://127.0.0.1:5173`。Vite 代理 `/api` 到后端 3000；连接凭据仍只由后端使用。`npm run check` 包含类型检查、lint、全部 Node 测试和构建；`npm run test:e2e` 需要已构建前端与安装好的 Playwright Chromium。

浏览器测试使用独立临时目录、固定本地端口 4100 和测试入口的假客户端。生产入口的重启测试使用端口 4101，验证初始化及会话持久化，不配置真实连接。没有生产“演示模式”或允许任意上游 URL 的开关。测试结束停止服务并清除临时数据库，截图仅含合成数据，放在被忽略的 `test-results/` 中。

## 常见错误

| 现象 | 处理 |
| --- | --- |
| 初始化令牌无效 | 在部署服务的机器读取启动日志所示位置的 setup-token |
| Origin 校验失败 | 使用 APP_ORIGIN 指定的地址，检查域名/协议/端口，无尾斜杠 |
| 登录过期 | 重新登录；会话有效期 12 小时；改密码会撤销所有设备会话 |
| 同步部分失败 | 打开总览中的任务，查看书籍 ID、类别和错误，再次同步 |
| UPSTREAM_FORMAT / UPGRADE | 上游结构或版本变化，需要适配客户端；已有记录会保留 |
| UPSTREAM_RATE_LIMIT | 稍后手动重试，不提高并发 |
| 进程启动失败 | 检查端口冲突、第二实例、目录权限、主密钥匹配和数据库版本 |

无自动任务时也需保持 Node 进程运行才能访问界面；需要开机启动时由部署者的系统服务管理器托管。M3 的后台调度和发送队列不依赖浏览器在线。

## 可视化规则与导入预览（M2）

1. 完成连接配置和一轮“读取完成”的完整同步，进入“规则”。
2. 设置类型、来源日期、关键词，书籍和作者始终不限制。日期按规则时区包含首尾两天；默认 Asia/Shanghai，支持有效的 IANA 时区。空筛选项不限制；多个条件同时满足才命中。
3. 关键词每行一个，使用字面量子串，英文大小写不敏感。选择正文、原文或两者；包含词支持任意/全部，排除词任意命中即排除。仅划线的文字保存在原文中。
4. 固定输出书籍信息、引用原文和非空想法，自动添加书名标签；可输入每行一个额外标签（不能含空格，支持层级斜杠），点击“预览匹配与导入文本”。可翻页查看条件命中、条件不符和纳入范围的笔记；条件修改后旧预览清空。
5. 默认只处理启用后首次发现的新 ID。启用前的匹配样例不会进入新增范围；已入库记录后续修改也不会变成新记录。若需要历史内容，选择包含历史并明确确认。
6. 保存草稿或启用规则。启用规则只保存处理策略。随后在“自动任务”页准备队列、检查内容并明确启用自动导入；预览不是已导入数量。

启用前最近一轮必须完整成功，笔记本遍历及所有书籍的划线/想法范围均成功，且没有正在运行的同步。该基准表示本项目完整遍历了上游可返回数据，不代表已验证上游快照/删除契约。若页面报告基准不足，先重新完整同步。

停用再启用保留原基准，因此停用期间新入库的笔记仍可能纳入范围。已建立基准后不能修改历史范围；请复制成新规则。规则的连接身份保存后不能修改，复制可重新选择当前连接。换任一连接会停用关联规则，不会把旧基准转移到新账号。两个页面同时编辑会拒绝过期修订，请重新打开规则。

每条来源记录对应一条预览；同时选划线与想法可能包含相同原文。缺失原文、章节等会标注，不猜测。接口没有已验证的阅读链接字段，因此 M2 不生成或提供链接开关。文本不截断、不拆分；发送阶段按本应用字数保护值阻塞超长内容；多规则按笔记/目标去重，选择最早创建规则的输出。官方记录 API 的实际字数上限仍待验证。当前预览扫描该连接的本地笔记，响应每页最多 20 条；未做大规模数据性能验收。

升级前停服务并备份数据、独立主密钥和旧程序文件。当前程序自动将旧数据库迁移到版本 6，保留已有连接、笔记、规则和会话。旧版本程序会拒绝较新的数据库；回退须恢复匹配的升级前备份，不能直接覆盖数据库版本号。

固定导入文本示例：

```text
《合成书籍（Reading Habits）》 示例作者 · 第一章
> 这里是标记的原文。
📝 想法：这里是自己的思考。
#微信读书/合成书籍（Reading_Habits）
```

实际发送文本的模块间只换行，不额外加空行；正文原有换行保留。网页预览使用少量 CSS 段间距区分模块，不把这段视觉间距写入发送文本。没有想法正文就省略想法段。导入时清理原文首尾空白；多行原文仅对非空行添加 `> `，内部空白行保留为普通空行。本地保存的原文不变。书名标签中的空白转换为下划线，# 和 / 也转换为下划线；显示用的书名不做此替换。缺失书名、作者、章节或原文会明确标注。创建时间仍用于筛选和笔记浏览，不写入 flomo。

数据库迁移 004 将旧规则移除书籍/作者限制和输出字段开关，使用固定格式，并移除被自动书名标签替代的单独 `#微信读书` 标签；其他自定义标签、日期、关键词、历史基准和启停状态保留。规则修订号增加，已发送记录及去重身份保持不变。升级后先预览新规则范围再启用自动导入。

## 自动任务与导入（M3）

进入“自动任务”，设置后点击保存。首次安装两个开关默认关闭，升级保留已有开关状态。默认周期为 15 分钟，可改为 5 分钟至 7 天；也可选择每天的具体时刻及 IANA 时区。间隔模式在本次结束后计算下一次；每日模式按该时区的下一次时刻计算，处理夏令时。停机错过多次计划只补一次，任务不重叠。

完整模式每次重新遍历全部笔记。轻量模式使用笔记本概览指纹，只读取变化、新增、没有成功指纹或未出现在当前概览中的书籍；失败不推进指纹。距上次完整成功读取达到 24 小时会强制完整读取。轻量模式可能漏掉不反映在概览中的变化，适合接受延迟并希望减少请求的用户。手动同步始终完整读取；启用新规则前最近一轮仍须是完整成功读取。

同步失败后按 1、2、4、8…分钟退避，最多 1 小时，若正常周期更短则按较短时间运行。认证失效、接口升级或明确拒绝会暂停自动同步；修改配置后可重新启用。不会用失败读取推断删除。

“按规则准备队列”仅更新本地任务，便于导入前检查。自动导入启用后每分钟、每轮自动同步结束及规则变更后更新队列；发送前仍重新匹配。若规则多重命中，同一笔记/目标只有一条任务，使用最早创建规则（时间相同按 ID 排序）的输出，保存所有命中规则及修订。原文相同但来源 ID 不同的划线/想法仍是两条记录。来源修改不自动修改已导入的 flomo 笔记。

flomo 写入至少间隔 5 秒。所有尝试（包括可能成功和被拒绝的请求）计入本实例滚动 24 小时配额，默认 100，可调低；这不是对官方自然日重置时刻的假定，也无法得知其他工具的用量。单条默认 5000 Unicode 字符保护值可调整，不是已验证的官方记录 API 上限；超限显示阻塞，不截断、不拆分。目标实际拒绝仍会阻塞并显示状态。

- HTTP 429：遵守 Retry-After；没有有效值时至少等 5 分钟。
- 可证明连接尚未建立的 DNS/拒绝连接/连接超时：指数退避，最多共 5 次自动尝试，之后阻塞并暂停导入。
- 写入请求超时、连接重置、未知响应、HTTP 408/5xx 或发送进程中断：仅该任务待核对，不自动重发；其他正常任务继续。
- HTTP 401/403、其他明确 4xx 或非零业务码：阻塞并暂停导入，检查权限、内容和额度后手动恢复。

在详情查看文本和尝试记录，核对 flomo 后选择“已在 flomo 找到，标记完成”或“确认未导入，允许重试”。重试仍遵守当前规则、全局冷却时间和额度。暂停再启用、更改设置、人工恢复均不清除冷却时间。不能承诺 exactly-once。

服务重启保留同步和导入开关。导入前必须完成本次启动后的一次完整同步；失败时退避等待，不能直接发送旧队列。未完成发送转为待核对，其他正常任务继续。已发送去重、重试次数、额度和冷却时间保留；用户主动关闭的任务不会被自动打开。账号失效等运行阻塞独立保存，重启不会解除。更换任一连接也暂停两个自动任务并取消未发送任务。自动任务只有服务进程运行时才能执行，需由部署环境的进程管理器保持运行。

版本 3 自动迁移保留原有规则、基准、笔记、连接与会话。升级/回退仍须备份数据、主密钥和对应程序文件。恢复旧备份可能丢失恢复点之后的已发送记录；在重新启用发送前需核对这些历史记录。

## 想法缺失与删除核对（0.3.2）

- 每本书的想法都从第一页重新读取。只有全部分页成功、没有重复 ID/游标、每页总数一致且与实际数量一致，才能把缺失算作一次证据；如概览提供顶层 reviewCount，也须一致。缺少总数时仍可更新读到的内容，但未读到的旧想法暂停导入、不判定删除。
- 首次有效缺失标记“疑似删除，待复核”，同一事务内挂起未发送任务。第二次独立同步中的有效缺失标记“已删除（同步推断）”，取消未发送任务。次数按该书的完整想法核对计算，不把同一轮的分页或请求重试算成多次；其他书籍失败不影响该书的有效核对。
- 读取失败、数量不符或分页异常会暂停受影响想法的导入，并将连续缺失次数重置为 0；已发现缺失的想法保持待复核。连接级失败或整轮中断暂停该连接的相关任务。重启不会绕过暂停；中断的核对也不作为删除证据。
- 单书或本轮有效核对范围缺失至少 5 条且占一半以上，或本轮至少两本已有想法的书同时全部变空，触发异常保护：保留内容、暂停相关导入、不推进删除计数。核对来源后再次同步；持续异常会继续暂停，当前没有强制绕过按钮。
- 书籍从概览消失，仍用旧 bookId 查询。轻量模式对待复核或暂无法核对的书强制读取；跳过的书不计核对次数。建议需要及时发现删除的用户选择每 15 分钟完整读取；轻量模式可能延迟发现首次缺失。
- 原 ID 重新出现时恢复正常、清除缺失计数，原任务仍用相同 ID，发送前重新匹配规则。原有 flomo 限流冷却、重试次数和阻塞原因保留；恢复来源不会自动解除 flomo 自身的失败阻塞。
- 已成功导入和结果不确定的尝试记录保持原样，不修改或删除 flomo 内容。来源未恢复时不能手动重试发送；不确定任务仍可人工确认“已在 flomo 找到”。在途请求不能撤回，手动同步与发送会互斥。

笔记库可按来源状态筛选，详情展示首次缺失时间、连续有效核对次数及删除标记时间。导入记录可筛选“来源待复核”，查看挂起原因。数据库只做软删除，不清除原文、想法、来源 ID 或发送历史。

## 重启与备份恢复（0.3.3）

生产入口将独立发送检查记录保存在 `SECRETS_DIR/delivery-checkpoint.json`，数据库保存对应的实例标识和检查值。每次写入 flomo 前，先持久化并 fsync 检查文件，再在同一数据库事务内更新检查值与发送尝试，事务提交后才发送 HTTP。文件领先数据库、缺失、损坏或实例不匹配时，自动导入进入“备份恢复保护”。普通保存设置无法解除保护。

正常升级首次建立检查记录前也需要核对；保留当前数据的受控停机升级可以在校验所有旧记录后建立初始检查记录。恢复旧数据则必须核对 flomo 中已经存在的笔记，并调整规则范围排除可能重复的历史记录。页面确认只建立新的检查基准，不能找回旧备份之后丢失的成功记录。

恢复备份请先停止应用，保留与备份匹配的主密钥，在项目目录执行：

```sh
npm run restore -- --from /绝对路径/备份/app.sqlite
```

恢复工具取得实例锁，检查数据库完整性、版本、外键和密钥解密，保留替换前的数据库副本，然后替换数据库并强制设置恢复保护。启动后在“自动任务”的“备份恢复保护”区域核对并确认；确认不会打开原本关闭的开关，已启用的导入会在完整同步成功后恢复。不要通过手工覆盖数据库绕过恢复流程。

数据库与检查文件同时被整机镜像回滚时，本地无法识别；这种恢复也必须执行上述恢复流程，即便输入数据库与回滚后数据库内容相同（从另一份文件路径恢复）。如需自动识别整机回滚，必须使用设备外的持久化检查记录，当前版本不提供。

## 源码与个人数据分离（0.3.4）

默认应用数据目录按运行程序的用户确定，与源码放在哪里无关：

| 系统 | 应用数据目录 |
| --- | --- |
| Linux | `$XDG_DATA_HOME/weread-flomo`；未设置或不是绝对路径时为 `~/.local/share/weread-flomo` |
| macOS | `~/Library/Application Support/weread-flomo` |
| Windows | `%LOCALAPPDATA%/weread-flomo`；未设置时为用户主目录下的 `AppData/Local/weread-flomo` |

其中 `data/` 保存数据库，`secrets/` 保存主密钥、首次设置令牌和发送检查文件；可选的 `config.env` 保存非秘密的启动配置。复制模板时先创建自己的外部目录。`DATA_DIR`、`SECRETS_DIR` 可覆盖两个存储目录，推荐使用绝对路径；不能指向源码内，包括通过软链接指回源码的目录。程序创建的私有目录权限为 700，数据库与密钥权限为 600；Windows 的账户访问控制需由部署环境管理。路径选择有跨平台单元测试，完整进程测试当前仅在 Linux 上验证。

旧版迁移顺序：

1. 停止应用，保持固定域名与隧道设置。备份整个数据目录（含 WAL/SHM）、密钥目录及旧程序；备份必须放在源码之外。
2. 将原来的 `data/` 和 `secrets/` 完整移动到外部私有位置。`master.key` 和 `delivery-checkpoint.json` 必须原样保留；不要只迁移主数据库文件，不要重新生成密钥。
3. 将原 `.env` 中的个人配置转入外部 `config.env`，或系统服务的环境变量；清除源码目录中的旧配置。同步更新服务的工作目录、`DATA_DIR`、`SECRETS_DIR`。还应移出 `backups/`、导出文件、诊断报告以及其他个人文件；不要在源码中创建指向私有目录的软链接。
4. 核对数据库记录、配置、密钥和发送检查记录一致后启动，确认登录、定时任务和公网访问正常。搬迁当前完整数据不属于回滚备份，无需解除或绕过恢复保护。真正恢复旧备份仍须使用恢复工具并人工核对。

源码中留有旧的 `data/app.sqlite` 时，启动和恢复命令会拒绝执行并提示迁移，避免意外初始化空库。恢复命令必须使用与运行服务相同的外部目录配置；系统服务设置的环境变量不会自动传递到另一个终端。

开源前执行 `npm run check`。仓库检查扫描源码，并额外检查 Git 已跟踪文件，防止强制加入的数据库、密钥和私有目录绕过 `.gitignore`。测试只使用临时目录中的合成数据。发布仅包含源码和示例配置；不要上传外部应用数据目录、备份、个人截图或诊断报告。凭据检查用于发现常见误提交，不能替代对任意个人文本及提交历史的审查。
