# 本地化与翻译

[English](localization.md) · [简体中文](localization.zh-CN.md)

## 运行行为

React 界面采用 [i18next](https://www.i18next.com/overview/configuration-options) 和 [react-i18next](https://react.i18next.com/latest/using-with-hooks)。语言文件随程序打包，不需要翻译 API、CDN 或额外网络请求。

语言优先级：

1. `localStorage['weread-flomo.language']` 中有效的手动选择：`en` 或 `zh-CN`。
2. 浏览器首选语言 `navigator.languages[0]`，无值则取 `navigator.language`：所有中文地区/文字变体，包括繁体，使用 `zh-CN`。
3. 其他语言或没有语言信息时使用英文。

不支持或过期的保存值会忽略。浏览器禁止存储不会阻止启动或切换，但选择只保留在当前标签页中。没有手动选择时会跟随浏览器语言变更；手动选择后优先使用该选择。偏好按浏览器和站点保存，不是跨设备账号设置；清除该项并刷新可恢复自动检测。

加载、初始化、登录页和登录后的页头均提供切换器。切换保留当前页面、表单输入和已获取的数据，并更新文档 `lang`、标题、界面文案和日期格式。笔记库仍用北京时间，规则与任务时区保持不变。

## 文件与键名

- `src/web/language.ts`：纯语言选择规则及存储键。
- `src/web/i18n.ts`：资源注册、初始化、持久化和文档元信息。
- `src/web/LanguageSwitcher.tsx`：共用切换器。
- `src/web/locales/en.json`、`src/web/locales/zh-CN.json`：完整语言资源。

键名采用可读的英文消息，是 i18next 支持的自然语言键形式。关闭 `keySeparator` 与 `nsSeparator`，因此句号、冒号是普通字符。修改译文时尽量保持键名不变；显示文案放在 JSON 值中，不在页面组件中散落译文。

界面通过 `t(key, values)` 获取文案。词序可能变化的动态句子使用完整消息及具名 `{{placeholder}}`，各语言必须保留相同变量名。涉及单复数的消息通过 i18next 的 `count` 参数处理，英文提供单复数形式，中文保留对应适用形式。状态和原因代码通过已知映射翻译，未知代码仍显示便于排错。错误状态保存代码，提示保存翻译键，不保存已翻译的结果，确保切换后已有提示即时变化。

React 会转义显示值。不要用 `dangerouslySetInnerHTML` 渲染翻译，也不要把 React 的转义配置照搬到不具备相同安全保障的渲染器。

## 来源数据不是界面文案

不翻译书名、作者、原文、想法、原始 JSON、账号名称、已保存的规则名、关键词、额外标签或发送内容。固定中文导入模板有意与界面语言独立，预览必须与 flomo 实际发送内容一致；只翻译周围的说明。新建草稿的默认名称可采用创建时的语言，之后作为用户数据保留。

切换语言不得修改数据库、触发同步/发送、重置基准、改变时区或修改队列文本。

## 添加新语言

1. 复制 `en.json` 为对应语言文件，翻译所有值，保留插值及该语言适用的复数形式。
2. 注册资源，扩展支持的语言类型和列表，并明确调整自动选择规则。
3. 在切换器增加用该语言自称显示的选项，更新保存值校验。
4. 扩展选择规则、语言资源和浏览器测试，检查桌面和手机上的长文案。
5. 添加对应文档，并在顶部提供语言切换链接；相关说明同步维护。

当前只提供两个版本，将来可以单独增加繁体中文语言文件，不需要改变笔记数据。

## 文档约定

默认英文使用 `README.md`、`docs/usage.md`、`CONTRIBUTING.md` 等规范名称，中文使用 `.zh-CN.md`。每篇顶部互相链接，中文版内部优先链接中文版。`README.en.md` 保留为旧链接的兼容入口。`LICENSE` 保留标准英文 MIT 许可，`LICENSE.zh-CN.md` 仅供理解、不替代原文。Issue 模板可选择中英文，默认 PR 模板链接中文版。

运行 `npm run check` 和 `npm run test:e2e`；截图和语言验证仅使用合成内容。
